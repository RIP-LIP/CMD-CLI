# 读文件：什么时候该用 cat，什么时候必须用 less

> 读完你会知道该用哪条命令读文件，以及为什么 `cat` 一个大日志会把终端卡死。这一章大约 18 分钟。

<ModuleMeta module-id="02-view" />

## 前置条件

确认你有文件可读：

```bash
ls -l /etc/hosts
```

## 1. 四个命令的分工

| 命令 | 读的范围 | 适合 |
| --- | --- | --- |
| `cat` | 全文 | 小文件，一次读完就够 |
| `less` | 全文，可翻页 | 大文件，要前后找 |
| `head` | 前 N 行 | 开头几行就够 |
| `tail` | 后 N 行 | 日志末尾、记录结尾 |

**判断标准只有一个：这个文件你打算读几遍。**

读一遍用 `cat`，要来回翻用 `less`，只看头尾用 `head` / `tail`。

## 2. 为什么 cat 会卡住终端

```bash
cat /var/log/syslog
```

如果你在真实机器上敲这条，会发生这样的事：输出迅速滚过屏幕，终端进入一种「看起来卡死」的状态。

**它没有卡死。** 终端在接收并渲染几 MB 文本，同时把这些文本往回滚缓冲区里塞。等全部渲染完，shell 提示符才回来。

真正的坑是：这时候你敲的按键**全被 cat 吞掉了**，包括 Ctrl+C。你以为按了中断，其实什么都没发生，只能等它自己跑完。

::: warning 判断标准：先看文件多大
```bash
ls -lh /var/log/syslog
```
超过几百 KB 就别直接 `cat`。养成习惯：**不确定大小的时候用 `less`，它对大文件和小文件一样安全。**
:::

## 3. less 的按键

```bash
less /var/log/syslog
```

进入后：

| 按键 | 作用 |
| --- | --- |
| `↓` `↑` | 上下翻一行 |
| `空格` / `b` | 下翻 / 上翻一整屏 |
| `/关键词` | 向下搜索 |
| `n` / `N` | 跳到下一个 / 上一个匹配 |
| `g` / `G` | 跳到文件开头 / 结尾 |
| `q` | 退出 |

**`/` 搜索是 less 的核心。** 打开一个几千行的日志，第一件事是 `/` 搜关键词，而不是先往下滚。

搜索还会高亮所有匹配项 —— 这比 `grep` 更适合「我想看看这个词在文件里出现在哪些地方」。

::: tip less 支持边看边加载超大文件
打开一个 20 GB 的日志，less 不会一次读进内存，它只读当前显示的那一屏。这也是它比 `cat` 适合大文件的原因，不只是「能翻页」。
:::

## 4. head 与 tail

```bash
head -n 5 /etc/hosts
```

```bash
tail -n 5 /etc/hosts
```

`head` 和 `tail` 默认都是 10 行，`-n` 指定行数。

`-n 5` 和 `-5` 等价，短形式更常见：

```bash
head -5 /etc/hosts
```

### tail 的实时跟随

```bash
tail -f /var/log/syslog
```

`-f` 会一直等新内容追加进来并实时打印。**这是看服务日志的默认动作。**

::: warning `-f` 不会退出
`tail -f` 一直在等，Ctrl+C 才能停。排查时用错地方会以为终端卡住了 —— 它只是在等。

退出用 Ctrl+C，不是 `q`（`q` 是 less 的退出键，tail 没有分页）。
:::

组合起来看文件「最后 100 行并且实时跟」：

```bash
tail -n 100 -f /var/log/syslog
```

## 5. 统计与截取

```bash
wc -l /etc/hosts
```

`wc` 数三样东西：行数、词数、字节数。不带参数时三个都出：

```bash
wc /etc/hosts
```

带 flag 只出其中一样：

```bash
wc -l /etc/hosts   # 只要行数
```

::: warning 管道里 wc 读的是 stdin
```bash
cat /etc/hosts | wc -l
```
等价于 `wc -l /etc/hosts`。但在真实系统上更该写后者 —— 前者多了一个进程和一次磁盘读，文件大时差别明显。
:::

截取中间几行用 `sed`，那是下一章的内容。

## 排障

**Q1：终端「卡死」了，怎么中断？**

按这个顺序：
1. 按一次 `Ctrl+C` —— 大多数情况这就够了
2. 如果没反应，按 `Ctrl+Q` —— 这是 XON/XOFF 流控，`cat` 输出太快把终端塞满时能救回来
3. `Ctrl+Z` 挂起进程（暂停，不是杀掉），之后用 `fg` 恢复、`kill %1` 彻底结束

**Q2：`tail -f` 屏幕一直不动，是不是日志没更新？**

1. `tail -n 5 日志路径` —— 不带 `-f` 看最后 5 行有没有内容
2. `ls -l 日志路径` —— 看文件大小和修改时间，是不是真的没写
3. `journalctl -f` —— 如果是 systemd 管理的服务，日志走 journald，文件里看不到是正常的

**Q3：`head -20` 和 `head -n 20` 有区别吗？**

没有，两者等价。但 `head -2file.txt` 会被解析成「显示前 2 行，文件是 file.txt」，参数和值必须分开写。

## 什么时候别用

| 场景 | 别用什么 | 用什么 |
| --- | --- | --- |
| 文件超过几百 KB | `cat` | `less` 或 `head` / `tail` |
| 只想看某几个字段 | `cat` + 眼睛扫 | 管道给 `grep` / `awk`（下一章） |
| 日志排查 | `cat` 整个文件 | `tail -f` + `/` 搜索 |
| 二进制文件 | `cat` | 会输出乱码并可能卡住，用 `file` 先确认类型 |

**`less` 也不是万能的**：它一次只在一个文件里翻。要跨文件聚合、排序、筛选，管道比 `less` 合适。

## 哪些是通用的

| 这里学的 | 别处对应 |
| --- | --- |
| 先看大小再决定怎么读 | 任何环境下都成立 |
| 实时跟随日志 | Windows 是 `Get-Content -Wait -Tail 20` |
| 翻页器按键习惯 | `more`、`most` 基本兼容 |

**不通用的是命令名**。Unix 这一套在 Windows 上要换成 PowerShell 的 cmdlet，但「读一次 vs 读很多次」这个判断标准是一样的。
