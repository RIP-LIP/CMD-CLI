# 在终端里不迷路：定位与创建文件

> 读完你会有一双能定位的眼睛：任何时候敲一条命令就知道自己在哪、这里有什么、哪些能删哪些不能删。这一章大约 20 分钟。

<ModuleMeta module-id="01-intro" />

## 前置条件

先确认你用的是 bash，不是别的 shell：

```bash
echo $SHELL
```

应该输出 `/bin/bash` 或 `/usr/bin/zsh`。如果输出 `fish`，本章的 `$` 提示符会略有不同，其余命令一样。

再看一眼你的当前位置：

```bash
pwd
```

## 1. 先建立三个问题的答案

新手在终端里最常卡住的一句话是「我在哪」。养成一个习惯：**任何时候不确定，先敲 `pwd`**。

```bash
pwd
```

你应该看到：

```bash
/home/max
```

`pwd` 是 print working directory 的缩写。它永远返回一个**绝对路径** —— 从根目录 `/` 开始写的完整路径。

### 提示符里的路径是缩写

终端提示符通常长这样：

```bash
max@devbox:~/projects$
```

这里的 `~` 是 `/home/max` 的缩写。含义是：你现在在家目录下，提示符为了省地方只写了 `~`。

| 提示符里 | 实际路径 |
| --- | --- |
| `~` | `/home/max` |
| `~/projects` | `/home/max/projects` |
| `/` | `/` |
| `../..` | 往上两级（这个是相对写法，不是绝对路径） |

**绝对路径永远从 `/` 开始，中间没有歧义。** 写脚本、配置文件时一律用绝对路径，这是隐性规则里最省事的一条。

## 2. 看这里有什么

```bash
ls
```

你应该看到：

```bash
projects  readme.md  notes.txt
```

`ls` 是 list 的缩写，默认**只列名字，不显示大小和时间**。

### 三个必记选项

| 选项 | 作用 |
| --- | --- |
| `-l` | 详细列表：权限、属主、大小、时间 |
| `-a` | 包含以 `.` 开头的隐藏文件 |
| `-h` | 大小用 KB / MB / GB 显示 |

日常最常用的是 `ls -lah`，三个合起来：

```bash
ls -lah
```

你应该看到：

```bash
total 3
-rw-r--r-- 1 max max  9 Aug 21 10:23 notes.txt
drwxr-xr-x 1 max max 4096 Aug 21 10:23 projects
-rw-r--r-- 1 max max 22 Aug 21 10:23 readme.md
```

::: warning `-h` 单独用在 `ls` 上没有意义
`ls -h` 不带 `-l` 时不会改变任何输出，因为它只影响详细列表里的那一列大小。想让人性化大小生效，必须同时有 `-l`。这是文档里不写、但会让人以为命令写错了的地方。
:::

### 第一列权限位怎么读

`drwxr-xr-x` 这一串，前 10 个字符有固定含义：

```
drwxr-xr-x
│└┬┘│└┬┘│└┬┘│
│ │  │ │  │ └─ 其他人
│ │  │ │  └─── 所属组
│ │  │ └────── 属主
│ │  └──────── 属主权限
│ └─────────── 所属组权限
└───────────── 文件类型（d 目录 / - 普通文件）
```

属主、所属组、其他人各三个字母：`r` 读、`w` 写、`x` 执行。

## 3. 切换目录

```bash
cd projects
```

`cd` 是 change directory 的缩写。

- `cd ..` —— 上一级
- `cd ~` 或 `cd` —— 回家目录
- `cd /` —— 回根目录
- `cd -` —— **回到上一次所在的目录**

::: tip `cd -` 是 bash 的特性，不是 POSIX 标准
它把上一个目录记在 `$OLDPWD` 里，在两处反复横跳。写脚本时不要依赖它 —— 脚本的非交互环境下这个行为可能不一致，而且它依赖调用者的历史，不是脚本自己的。脚本里存路径就用变量。
:::

`cd` 不带参数会回家目录，这是最省事的默认行为。

## 4. 创建目录和文件

```bash
mkdir -p /tmp/practice/deep
```

`-p` 是 parents 的意思，会把不存在的父目录一起建上。

::: warning 这是「隐式创建」，不是「覆盖」
`mkdir -p` 遇到已存在的目录**不报错**，静默跳过。好处是脚本可以重复执行；坏处是你以为建了目录，其实早就在那了。排查脚本问题时，先 `ls` 确认现状，别假设 `mkdir` 一定成功。
:::

不用 `-p` 时，中间层不存在就会失败：

```bash
mkdir a/b/c
```

你会看到：

```bash
mkdir: cannot create directory ‘a/b/c’: No such file or directory
```

创建空文件用 `touch`：

```bash
touch /tmp/practice/hello.txt
```

::: warning touch 不会清空已有文件
`touch` 只改文件的修改时间戳。文件里有内容时用 `touch`，内容一个字都不会少。想清空内容得用 `>` 或 `truncate`，那是完全不同的操作。
:::

## 5. 删除，以及删除之前

```bash
rm -i /tmp/practice/hello.txt
```

`-i` 是 interactive，每个文件都问一次。**建议所有手动删除都加 `-i`。**

常用选项：

| 选项 | 作用 | 危险程度 |
| --- | --- | --- |
| `rm -i 文件` | 逐个确认 | 安全 |
| `rm 文件` | 直接删，不提示 | ⚠️ 手滑就没了 |
| `rm -r 目录` | 递归删目录及其内容 | ⚠️⚠️ |
| `rm -rf 目录` | 递归 + 强制，不提示 | ⚠️⚠️⚠️ |

::: danger `rm -rf /` 会删掉整台机器
在 Linux 上 `rm -rf /` 从根目录递归删除，没有回收站，没有确认，执行完系统就废了。这条命令在运维事故里出现过多次。

真实的 shell 对 `rm -rf /` 有保护，会拒绝并提示 `use --no-preserve-root to override`。但 `rm -rf /*`（注意星号的位置）**绕过了这个保护**，因为它的目标不是根目录本身。

养成习惯：手动删除永远带 `-i`，脚本里删除前先 `echo` 一遍路径。
:::

### 删错了怎么找回来

Linux 没有回收站。删掉就没了，这是最需要记住的一条。

补救办法只有一个：**如果文件系统是 ext4，尝试 `debugfs`**：

```bash
# 需要 root，且需要立刻操作，磁盘被写过之后可能已被覆盖
sudo debugfs -w /dev/sda2
# 然后在 debugfs 里用 lsdel 列出最近删除的 inode
```

这是最后手段，成功率不高。在云主机上更该做的是**从备份恢复**。

## 6. 复制与移动

```bash
cp notes.txt notes.bak
mv notes.bak /tmp/
```

- `cp 源 目标` —— 复制
- `mv 源 目标` —— 移动或重命名

::: warning 目标已存在时，cp 和 mv 行为不同
`cp a.txt b.txt` 在 `b.txt` 已存在时**直接覆盖**。
`mv a.txt b.txt` 也是覆盖。

但如果目标是**已存在的目录**，两者都会把文件放进目录里，而不是覆盖同名文件 —— 这个差别只在目标已存在时才体现，容易误判。
:::

**重命名不需要新命令**：`mv old.txt new.txt` 就是重命名。

## 排障

**Q1：`cd /tmp` 之后发现文件不见了？**

按这个顺序查，不要跳步：

1. `pwd` —— 确认你现在真的在 `/tmp`
2. `ls -la` —— 加 `-a`，因为你可能找的是隐藏文件
3. `ls -la /tmp` —— 用绝对路径再看一次，排除相对路径歧义

**Q2：`mkdir a/b/c` 报 No such file or directory，但 `a` 明明存在？**

1. `ls -la a` —— 确认 `a` 是**目录**，不是文件。同名的文件和目录会互相遮挡
2. `ls -la a/b` —— 逐层往下看，可能是中间某层是文件
3. `mkdir -p a/b/c` —— 直接用 `-p`，让它自己处理

**Q3：明明在目录里，`cat file.txt` 却说找不到？**

1. `pwd` —— 你可能在上一层目录，提示符的 `~` 容易看漏
2. `ls` —— 文件名可能有大小写差异，或多了看不见的空格
3. `ls | cat -A` —— 显示行尾，`$` 标记行尾，能看出尾随空格。文件名带尾随空格是脚本里的经典坑

## 什么时候别用

| 场景 | 别用 | 用什么 |
| --- | --- | --- |
| 要找「名字像什么」的文件 | `find` 全盘遍历 | 先想清楚目录范围，`find /etc -maxdepth 2` |
| 要读一大段文本 | `cat` | `less`（下一章） |
| 要批量删除 | 手敲多个 `rm` | 先 `find` 出清单看一眼再删 |
| 交互式手工操作 | 记一堆 `cp`/`mv` 参数 | 练熟了再谈脚本化 |

::: danger 什么时候**必须**不用
如果你在一台生产服务器上，手上没有第二个终端、也不确定当前目录 —— **先不要敲任何删除命令**。

`rm` 没有回收站，`rm -rf` 打错一个字符就没有任何挽回余地。这时候唯一正确的动作是 `pwd` 确认位置，`ls` 看清内容，然后再决定。
:::

## 哪些是通用的

这一章的思路换个平台照样成立：

| 这里学的 | 在 Windows 上对应 |
| --- | --- |
| 「先定位，再操作」 | `cd` / `dir` 一样 |
| 绝对路径 vs 相对路径 | `C:\Users\MAX` vs `.` |
| 删除前先确认 | `del` 加不带提示，`rd /s` 才是递归 |

**不通用的是具体的选项字母**。`-lah` 是 GNU coreutils 的约定，BSD 的 `ls` 上 `-h` 行为略有不同，macOS 上 `ls` 默认就不带颜色。不必背每平台的差异，先在目标机器上敲一次 `ls --help` 看它认什么。
