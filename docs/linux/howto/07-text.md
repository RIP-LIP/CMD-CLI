# 文本三件套：grep / sed / awk 各自负责哪一段

> 读完你能判断一个需求该交给 grep、sed 还是 awk，而不是三个都试一遍；并且知道 `sed s///` 不加 `g` 只改第一处这类会静默出错的地方。约 30 分钟。

<ModuleMeta module-id="07-text" />

## 前置条件

```bash
command -v grep sed awk
```

你应该看到三条路径。**少任何一个，先装再往下**：`sed` 和 `awk` 属于 POSIX 要求的最小集合，Debian/Ubuntu 上是 `sed` 和 `gawk`/`mawk` 包。

准备一个贯穿本章的样本文件：

```bash
mkdir -p /tmp/text-lab && cd /tmp/text-lab
cat > access.log <<'EOF'
2026-10-04 10:00:01 INFO  192.168.1.10 GET  /index.html 200 1024
2026-10-04 10:00:03 WARN  192.168.1.11 GET  /api/user   500  128
2026-10-04 10:00:07 ERROR 192.168.1.11 POST /api/login  401   64
2026-10-04 10:01:00 INFO  192.168.1.12 GET  /api/user   200  2048
2026-10-04 10:01:12 ERROR 10.0.0.5     GET  /api/order  502  512
EOF
```

**你应该看到 5 行，字段固定为「时间 日期 / 级别 / IP / 方法 / 路径 / 状态码 / 字节数」。** 后面所有例子都基于它。

## 1. 先分清三个工具的职责

| 工具 | 它做的事 | 一句话判断 |
| --- | --- | --- |
| `grep` | **选行** —— 哪些行要留下 | 「我要找包含 X 的行」 |
| `sed` | **改行** —— 行内容替换、删除、打印 | 「每行里的 X 换成 Y」 |
| `awk` | **拆列** —— 按分隔符把每行拆成字段再算 | 「每行的第 3 列加起来」 |

**判断句：只筛选用 grep，只替换用 sed，一旦要「按列算」就上 awk。** 三个都能凑合做别人的活，但用错工具的代码别人读不懂。

## 2. grep：选行，以及它的退出码

| 选项 | 作用 | 是否改动数据 |
| --- | --- | --- |
| `-i` | 忽略大小写 | 只读 |
| `-n` | 打印行号（**排查时必加**） | 只读 |
| `-v` | 反选：打印**不**匹配的行 | 只读 |
| `-c` | 只打印匹配行数 | 只读 |
| `-l` | 只打印有匹配的文件名 | 只读 |
| `-w` | 全词匹配，避免 `user` 命中 `username` | 只读 |
| `-r` | 递归目录 | 只读 |
| `-E` | 扩展正则（`|`、`()`、`{}` 不再需要转义） | 只读 |
| `-o` | 只打印匹配到的那一段，不打整行 | 只读 |
| `-A2 -B2` / `-C2` | 连带上下 2 行 | 只读 |

```bash
grep -n 'ERROR' access.log
grep -c ' 500 ' access.log
grep -E '(500|502)' access.log
```

**第一条你应该看到行号 3 和 5，第二条应该看到 `1`。**

::: warning

grep 的退出码是脚本里最常见的一处静默失败
`grep` 的退出码有三种，含义完全不同：

| 退出码 | 含义 | 脚本里的后果 |
| --- | --- | --- |
| `0` | 找到了 | 继续 |
| `1` | **没找到**（不是错误） | **`set -e` 的脚本会在这里直接退出** |
| `2` | 真出错了（文件不存在、权限不足） | 退出 |

所以 `set -e` 的脚本里这一行是安全的：

```bash
if grep -q 'ERROR' access.log; then echo "有错"; fi
```

而这一行会**在「没有错误」的正常情况下杀掉整个脚本**：

```bash
grep -q 'ERROR' access.log
cleanup.sh      # 这一行在没有错误时根本不会执行
```

**判断句：脚本里只要可能出现「没找到」，就必须放进 `if` / `||` / `&&`，或者在 grep 后面加 `|| true`。**
:::

::: tip

`grep -r` 和 `grep -R` 不是一回事
`-r` 递归但**不跟随目录里的符号链接**，`-R` 会跟随。**机器上有软链指向大目录（比如 `/lib` 指向 `/usr/lib`）时，`-R` 会让搜索量翻几倍甚至陷入循环。** 习惯用 `-r`，确实需要穿透软链再加 `-L`。
:::

::: tip

用 `-I` 处理二进制文件
`grep` 遇到二进制文件会只输出一行 `Binary file xxx matches`，不给内容。**`grep -I` 把它当文本处理**，日志目录里混进了 core dump 或图片时这个选项有用。
:::

::: warning

字符类在中文/UTF-8 locale 下会多匹配
默认 locale 是 UTF-8 时，`grep '[a-z]'` **也会匹配到重音字母和部分非 ASCII 字符**。想让行为完全可预期、并且在大文件上更快：

```bash
LC_ALL=C grep -n '[a-z]' access.log
```

`LC_ALL=C` 让比较按字节进行。**在脚本里做严格的格式校验时加它**，否则同样的正则在一台机器上通过、另一台上不过。
:::

## 3. sed：改行，以及「只改第一处」

| 写法 | 作用 | 是否改动数据 |
| --- | --- | --- |
| `sed -n '/ERROR/p'` | 只打印匹配行 | 只读（`-n` 抑制默认输出） |
| `sed '/ERROR/d'` | 删除匹配行 | 只读（不 `-i` 时输出到屏幕） |
| `sed -E 's/old/new/'` | 替换 | 只读 |
| `sed -E 's/old/new/g'` | 每行全部替换 | 只读 |
| `sed -E 's/re/part/g; s/x/y/g'` | 多个命令用 `;` 串 | 只读 |
| `sed -E 's|/a|/b|g'` | **分隔符可换成 `\|`，路径里有斜杠时最省事** | 只读 |
| `sed -i.bak 's/old/new/g' 文件` | ⚠️ 原地改并留 `.bak` | ✅ 改文件 |
| `sed -i 's/old/new/g' 文件` | ⚠️ 原地改，无备份 | ✅ 改文件 |

::: warning

`s///` 不加 `g` 只替换每行的第一处 —— 而且不报错
这是 sed 最常见的一处静默错误：

```bash
sed -E 's/192.168/10.0/' access.log
```

**你会看到每行只有第一个 IP 被改了，第二个 `192.168.1.11` 原封不动，而且没有任何提示。** 因为 `s` 的默认行为是「每行只替换第一次出现」。

**判断句：`s///` 用于替换时默认加 `g`，除非你确实只想改第一处。**
:::

::: warning

`sed -i` 在 Linux 和 macOS 上不是同一个命令
GNU sed（Linux）写 `sed -i 's/a/b/' 文件`；BSD sed（macOS）必须写成 `sed -i '' 's/a/b/' 文件`，否则 `''` 会被当成脚本、文件名会被当成表达式，报一个看起来毫不相关的错。

**判断句：写死的脚本要跨 macOS，就用带后缀的 `-i.bak`。** 顺手留了备份，也不算坏事。
:::

### 按行号或范围改

```bash
sed -n '2,4p' access.log
sed '5d' access.log
```

**第一条你应该看到第 2 到 4 行；第二条你应该看到 4 行（原第 5 行被删）。** 行号是 1 起的，`$` 表示最后一行。

## 4. awk：拆列，这是 awk 唯一不可替代的能力

| 写法 | 含义 |
| --- | --- |
| `$0` | 整行 |
| `$1` `$2` | 第 1、第 2 个字段 |
| `NF` | 本行字段数 |
| `NR` | 已读的总行数（多文件时是全局累计） |
| `FNR` | 当前文件的行号 |
| `awk 'BEGIN{...}'` | 读入前执行一次 |
| `awk 'END{...}'` | 全部读完后执行一次 |
| `-F,` / `-F'\t'` / `-F':'` | 指定分隔符（**支持正则**） |

本样本的字段：$1=$2=时间与日期（两段），$3=级别，$4=IP，$5=方法，$6=路径，$7=状态码，$8=字节数。

```bash
awk '{print $3}' access.log
awk '$7 != 200 {print $7, $6}' access.log
awk '{sum += $8} END {print "总字节:", sum}' access.log
```

**第三条你应该看到 `总字节: 3776`。**

::: tip

统计时用 `+=` 而不是 `++` 次数累加
`awk '{c[$3]++} END {for (k in c) print k, c[k]}' access.log` 用数组按级别计数。**数组的 key 可以是任意字符串**，所以同一套写法能直接用来做去重计数、状态码分布、IP 排行，不用先 `sort`。
:::

::: tip

awk 用 `print` 不会改原文件
`awk '{print $1}' access.log` 只是输出到 stdout。**要把结果写回文件必须显式重定向**：

```bash
awk '{print $1, $4}' access.log > ids.txt
```

这是 sed 之外的另一个安全点：默认只读，别忘了 `>` 是你自己加的。
:::

::: warning

`awk -F,` 只切第一个逗号
`-F,` 指的是**单个字符**分隔符。如果一行里有 `a,b,c,d`，`$3` 是 `c` 而不是 `c,d`。**要让字段里保留分隔符，用 `cut` 而不是 `awk`**，或者给 awk 一个正则：

```bash
awk -F', *' '{print $2}'       # 逗号后可跟任意个空格
```

需求是「取第 2 到第 4 段」时：

```bash
cut -d, -f2-4 access.csv
```

**判断句：字段本身含分隔符 → 用 `cut`；要按字段计算 → 用 `awk`。**
:::

## 5. 常见需求 → 组合写法

**判断句：这些是能直接抄的骨架，替换掉分隔符和字段号即可。**

| 需求 | 写法 | 是否改动数据 |
| --- | --- | --- |
| 统计各状态码出现次数 | `grep -oE '^[^ ]+ +[^ ]+ +[A-Z]+' 文件 \| awk '{print $1}' \| sort \| uniq -c` | 只读 |
| 找出占空间最大的 10 个目录 | `du -x --max-depth=1 /var \| sort -h \| tail -10` | 只读 |
| 统计每行出现的独立单词数 | `tr -s '[:space:]' '\n' \| sort \| uniq -c \| sort -rn \| head` | 只读 |
| 只看 ERROR 上下各 2 行 | `grep -n -C2 'ERROR' 文件` | 只读 |
| 打印含某列最大值的整行 | `awk -F' ' 'NR==1{m=$7} $7>m{m=$7;l=$0} END{print l}' 文件` | 只读 |
| 去掉行尾 CR（Windows 来的文件） | `sed 's/\r$//' 文件 \| grep -n 'ERROR'` | 只读 |
| 两列文件横向对齐 | `column -t 文件` | 只读 |
| 统计字节里 4xx / 5xx | `awk '{print $7}' 文件 \| cut -c1 \| sort \| uniq -c` | 只读 |

::: tip

`sort` 必须紧挨 `uniq`，`uniq` 自己不排序
`uniq -c` **只合并相邻的重复行**，输入没排序时它几乎什么都不做。这是「为什么我数出来的每个都是 1」的唯一原因。**记住固定顺序：`sort \| uniq -c`。**
:::

## 排障

**Q1：脚本跑出来是空的，但手动执行看着没问题？**

按这个顺序查，不要跳步：

1. `echo $?` —— 上一条命令的退出码。**是 1 的话就是 grep 的「没找到」，不是故障**
2. 脚本里有 `set -e` 吗 —— 有的话它会在 grep 返回 1 时直接终止
3. 变量有没有加引号 —— `grep "$pat" file` 正确；`grep $pat file` 里 `$pat` 会被拆成多个参数，pattern 变成空
4. 文件是不是 CRLF —— `cat -A 文件 \| head -3`，行尾会显示 `^M$`，那你的模式串结尾就少匹配

**Q2：`sed` 改完文件内容没变化？**

1. 没加 `-i` —— `sed 's/a/b/' 文件` 只输出到屏幕，**文件原封不动**（这是默认行为，不是失败）
2. 加了 `-i` 但忘了 `-n`/`p` 配合 —— 检查命令顺序
3. 模式里的 `/` 没转义或换分隔符 —— 写成 `s|a|b|g` 试一次
4. `sed -i ''` 在 Linux 上会把 `''` 当文件名 —— Linux 用 `sed -i 's/a/b/' 文件`

**Q3：`awk` 输出的字段比预期少一个？**

1. `cat -A 文件 \| head -3` —— 看分隔符到底是不是你以为的那个（tab 显示为 `^I`）
2. 连续空格会被 awk 当成多个空字段 —— 指定 `-F' +'` 或先用 `sed 's/  */ /g'` 规整
3. `-F,` 切的是单个字符，一行里有两个逗号时字段数比你以为的多
4. `awk '{print NF}' 文件 \| sort -u` —— 看看各行字段数是否一致，不一致说明文件格式不规整

**Q4：中文乱码 / grep 匹配不上中文？**

1. `echo $LANG` —— 非 UTF-8 环境按字节匹配，模式串里的中文对不上
2. `file 文件` —— 看文件本身是什么编码
3. 两边编码不一致时先用 `iconv -f GBK -t UTF-8 文件` 转换再匹配
4. `LC_ALL=C` 能让行为可预期，但**不会修正编码**，只是不再猜

**Q5：`grep -r` 在某个目录里不报错但漏掉文件？**

1. `grep -rn 'x' 目录 2>&1 \| head` —— 权限不足的文件只是静默跳过
2. 加上 `--include='*.log'` 缩小范围
3. 目录是符号链接 —— `grep -rn` 不穿透，用 `grep -RLn` 或直接给出真实路径

## 什么时候别用

- **改配置文件不要用 `sed -i`。** 直接编辑文件更好，因为 `sed -i` 出错时你既不知道改了什么，也没有语法检查。**配置类文件的修改应该能被 review，而不是被一行正则覆盖。** 要批量改配置文件，先 `sed 's/a/b/g' 文件 > 文件.new` 看 diff，确认后再替换。
- **不要用 `awk` 做 grep 能做的事。** `awk '/ERROR/'` 能跑通，但没人能一眼看出你想筛选。**`grep` 存在的意义就是让「选行」这件事不用拆字段。**
- **不要在几十 GB 的文件上用 `sed` 或 `awk`。** 它们是逐行流式工具，内存不是问题，但时间敏感。**先用 `grep` 过滤再交给 `awk`**，管道本身就是优化。
- **不要把 `sort | uniq` 换成 `uniq | sort` 之外的任何「优化」**（比如加 `-S`、`--parallel`）。`uniq` 必须紧跟 `sort`，这是它的实现方式决定的，没有替代。
- **不要用文本工具处理二进制。** 会出现 `Binary file matches`、输出乱码、极端情况损坏文件。需要结构化数据就用 `jq`。
- **复杂的 awk 脚本不要写进一行。** 超过 20 行就该存成 `.awk` 文件：单引号嵌套会让它无法维护，而且 awk 本身没有版本管理帮你看清改了什么。

## 哪些是通用的

| 这一章的思路 | Windows 上对应什么 |
| --- | --- |
| 「管道串起多个小工具」 | PowerShell 管道，但**传的是对象不是文本** |
| 「grep 选行」 | `Select-String` / `findstr` |
| 「sed 改行」 | `(Get-Content) -replace` |
| 「awk 拆列算」 | `Import-Csv` / `ForEach-Object` |
| 「先 filter 再 process」 | 完全一样，而且更重要 |

**不通用的是两处。** 一是工具名和选项字母（`-E`、`-i`、`-v` 都没有对应物）；二是 **PowerShell 的管道传的是对象**，`Select-String` 的结果带着行号和文件路径属性，可以直接 `.Line` 取出来，而 Unix 的管道传纯文本，取行号得靠 `grep -n`。这条差异在写跨平台脚本时会咬人。

**真正跨平台的原则只有一条：能用管道表达的就别写循环，能用一处替换的就别逐行处理。** 这条在两个平台都成立。
